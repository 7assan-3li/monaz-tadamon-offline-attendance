# إرشادات وقواعد تطوير مشروع تحضير نادي التضامن (MONAZ)

يجب تفعيل واتباع هذه المهارة كمرجع ملزم عند كتابة أو تعديل أي موديول في المشروع:

---

## 1. موجهات تطبيق Flutter و SQLite (Drift)

### أ. المعمارية الهندسية (Clean Architecture + MVVM via BLoC):
1. **تقسيم الميزات (Feature-First):**
   * كل ميزة تحتوي على مجلداتها المستقلة: `domain/`, `data/`, `presentation/`.
2. **الـ ViewModel المنضبط:**
   * كلاس `Bloc` هو الـ ViewModel؛ يستقبل `Events` ويبث `States` غير قابلة للتعديل (`immutable`).
   * يُمنع وضع أي استدعاءات لقاعدة بيانات Drift مباشرة داخل الواجهات (`Widgets`).
3. **مكتبة الـ Custom Widgets ومنع التكرار (Strict DRY):**
   * **قاعدة صارمة:** أي عنصر واجهة (زر، بطاقة، حقل إدخال، شارة حالة، مربع حوار) يُستخدم في أكثر من موضع يُبنى فوراً كـ `Custom Widget` في `core/widgets/`.
   * الشاشات (`screens/`) يجب أن تكون نظيفة وقصيرة، تركز على تجميع الـ Widgets وربطها بالـ BLoC.
4. **تطبيق مبادئ SOLID:**
   * **S:** ويدجت واحدة = مسؤولية بصرية واحدة.
   * **D:** حقن المستودعات والـ UseCases عبر `GetIt`.

### ب. قاعدة البيانات والتشغيل المنفصل 100%:
1. **العمل دون اتصال 100%:**
   * حظر تام لأي مكتبة تقوم بـ HTTP Requests أو فحص الاتصال بالإنترنت لبدء العمل.
   * الخطوط العربية (`Cairo`) والأيقونات مضمنة محلياً بالكامل.
2. **استراتيجية الترحيل الآمن (Drift Schema Migrations):**
   * عند إضافة أي جدول أو حقل جديد:
     ```dart
     @override
     MigrationStrategy get migration => MigrationStrategy(
       onCreate: (m) async => await m.createAll(),
       onUpgrade: (m, from, to) async {
         // ترقية آمنة تمنع فقدان البيانات القديمة
       },
     );
     ```
3. **مسار قاعدة البيانات الدائم:**
   * حفظ ملف الـ SQLite حصراً في `getApplicationDocumentsDirectory()`.

## 2. موجهات لوحة تحكم المزود (Laravel 12 + PostgreSQL)

1. **المتحكمات النحيفة (Thin Controllers):**
   * كود الـ Controller لا يتجاوز 5-10 أسطر، ومهمته الوحيدة التنسيق بين الطلب والـ Action.
2. **حصر التحقق في Form Requests:**
   * كل فحص للمدخلات أو الصلاحيات يوضع في `FormRequest` مخصص.
3. **كلاسات الأفعال المستقلة (Single-Action Classes):**
   * عزل كل عملية عمل في كلاس داخل `app/Actions/` بميثود `execute()`.
4. **طبقة الخدمات (Services):**
   * عزل التشفير (Ed25519) وتوليد الباركود داخل `app/Services/`.
5. **الالتزام بـ DRY و SOLID:**
   * استخدام DTOs لمنع تمرير مصفوفات غير محددة النوع.

---

## 3. موجهات التفعيل والأمان (Offline Licensing)
1. التحقق من كود التفعيل يتم محلياً بواسطة التوقيع الرقمي `Ed25519` والمفتاح العام المضمن في التطبيق.
2. المفتاح الخاص السري محفوظ حصراً داخل Laravel ويُمنع وضعه في Flutter.
3. فحص `High-Watermark` الزمني إلزامي قبل كل عملية اعتماد كشف أو حفظ مسودة لمنع التلاعب بساعة الجهاز.
4. معرّف الجهاز `Device ID` يُشتق برمجياً من عتاد الجهاز ولا يُخزن كمتغير عشوائي بسيط.

---

## 4. موجهات التدفق الميداني (UX & Field Flow)
1. **التحضير السريع (أقل من 30 ثانية):**
   * تجهيز جلسة تمرين اليوم تلقائياً دون إجبار الإداري على تعبئة استمارة.
   * زر «تحديد الجميع حاضر» يضع الكل حاضراً بنقرة واحدة، ويتم تعديل الغائبين فقط.
   * الحفظ كمسودة يتم لحظياً في الخلفية.
2. **استبعاد المالية تماماً في V1:**
   * لا تضع أي حقول مالية، أسعار، أو مبالغ في أي واجهة أو قاعدة بيانات؛ والاستحقاق رياضي بحت.
3. **قفل الترحيل الفوري والمزامنة المحلية (Dispatch Lock & Offline Sync):**
   * بمجرد نقر زر «ترحيل التمرين إلى الإدارة» في جهاز الميدان، يُقفل التمرين فوراً محلياً (`is_locked = 1` و `is_dispatched = 1`) وتُعطل كافة أزرار التعديل والحفظ.
   * المزامنة تتم محلياً دون أي اتصال بالإنترنت عبر كود QR الترحيلي أو الربط اللاسلكي المحلي المباشر.
   * استخدام `session_uuid` لمنع تكرار إدراج التمارين عند إعادة المزامنة (`Idempotency`).

---

## 5. المعايير الصارمة للاختبارات الآلية (Strict Automated Testing Standards)

### أ. اختبارات تطبيق Flutter الميداني:
1. **اختبارات الوحدة (Unit Tests):**
   * اختبار الـ UseCases والكيانات الخالصة مع عزل المستودعات بمحاكيات (`mocktail`).
   * اختبارات الـ BLoC حصراً باستخدام حزمة `bloc_test` للتأكد من تسلسل الحالات (`emitsInOrder`).
   * اختبارات دوال الأمان (توليد وتأكيد توقيع Ed25519، اشتقاق HMAC، فحص ساعة الجهاز `High-Watermark`).
2. **اختبارات قاعدة البيانات والترحيل (Drift In-Memory Tests):**
   * تنفيذ اختبارات قاعدة البيانات عبر `NativeDatabase.memory()` لاختبار عمليات الـ CRUD والـ Queries دون الحاجة لنظام ملفات فعلي.
   * **اختبار الترحيل الإلزامي:** التحقق من دالة `MigrationStrategy` مع كل تعديل في الـ Schema للتأكد من عدم تلف بيانات الكشوفات السابقة.
3. **اختبارات ودجات الواجهة (Widget Tests):**
   * اختبار تفاعل الأزرار في `lib/core/widgets/` والتأكد من مطابقة متطلبات إمكانية الوصول والمساحة اللمسية (>= 48dp).

### ب. اختبارات لوحة تحكم المزود (Laravel 12):
1. **اختبارات الأفعال والخدمات (Unit Tests via Pest / PHPUnit):**
   * اختبار كل كلاس في `app/Actions/` للتأكد من تنفيذه السليم وحسابات التراخيص.
   * اختبار خدمات التوقيع الرقمي والتشفير وتوليد QR.
2. **اختبارات الميزات والتحقق (Feature Tests):**
   * اختبار كل `FormRequest` للتأكد من رفض المدخلات المشبوهة أو غير المكتملة وإرجاع رسائل تحقق ملائمة.

## 6. قائمة التحقق الإلزامية قبل إنهاء أي مهمة (Checklist):
- [ ] **قراءة ملفات المشروع المسبقة:** هل تمت مراجعة ملفات الفكرة (`Concept`) وخطة المرحلة (`Phase 1 Plan`) ودليل المراحل (`Stages`) وملف التقدم (`PROGRESS.md`)؟
- [ ] **حظر التوسع الوظيفي (Zero Scope Creep):** هل يخلو الكود تماماً من أي ميزة، زر، حقل، أو جدول غير منصوص عليه صراحة في وثيقة الفكرة وخطة المرحلة؟
- [ ] **تحديث سجل التقدم:** هل تم تحديث نسبة الإنجاز والمهام المكتملة في `PROGRESS.md`؟
- [ ] هل كُتبت اختبارات آلية (`Unit / Functional / Widget Tests`) تغطي التعديل أو الميزة الجديدة؟
- [ ] هل تم تشغيل الاختبارات والتأكد من اجتيازها بنجاح تام (`All Tests Passed`)؟
- [ ] هل يتم قفل التمرين فوراً بعد الترحيل في جهاز الميدان ومنع أي تعديل لاحق؟
- [ ] هل تتم المزامنة بين الجهازين 100% دون إنترنت مع ضمان عدم التكرار (`session_uuid Idempotency`)؟
- [ ] هل تم استخراج الودجات المكررة كـ `Custom Widgets` مستقلة ومحققة لمبدأ DRY؟
- [ ] هل تتبع الشاشات نمط Clean Architecture + MVVM via BLoC ومبادئ SOLID؟
- [ ] في لارافيل: هل المتحكمات نحيفة (Thin Controllers) والمنطق معزول في Actions/Services؟
- [ ] هل الكود يعمل بنسبة 100% في وضع الطيران دون إنترنت؟
- [ ] هل تضمن قاعدة بيانات Drift عدم مسح أي بيانات قديمة عند التحديثات؟
- [ ] هل خلت الشاشات والجداول من أي مبالغ نقدية؟
- [ ] هل تم استلهام التصميم البصري للواجهات (Flutter و Laravel) من مجلد `ux ui` مع الالتزام الصارم بنطاق الفكرة وحظر أي زيادات وظيفية؟
- [ ] هل تلتزم المشاريع والميزات بالتسميات الصريحة المعبرة (`tadamon_attendance_app/` و `monaz_license_portal/`) مع خلو الكود من الاختصارات المبهمة؟
- [ ] هل اتجاه الواجهة يدعم العربية بالكامل (RTL)؟
- [ ] هل الكود متوافق مع Flutter 3.47.5 و Dart 3.13.4 المثبتة بالجهاز؟
